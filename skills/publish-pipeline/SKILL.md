# Publish Pipeline（发布流水线）

## Class of Task

把一份已经存在的草稿，在**一次会话内**推到"已发布"状态。

## 设计前提（不要违反）

健哥的诊断已经确认：**他不缺内容，也不缺表达能力——他缺的是"发布"这个动作，因为他不相信自己表达的东西算数。**

所以本 skill 的目标函数是**摩擦最小化**：

- ❌ 不要变成质检清单。每加一道质量关卡，都是在帮那个审判官多设一道门。
- ❌ 不要问"要不要再打磨一下"。
- ✅ 只做三件事：扫红线、定形状、按下发送。

## When to Use

- "这个该发了" / "要不要公开" / "E1 怎么办" / "开源这个"
- 手里有成形草稿但停了超过一周
- 他在纠结平台、署名、暴露尺度

**不适用**：内容还没写（那是写作，不是发布）；他明确说"先不发，只是想清楚"。

## 五步（目标：30 分钟内走完）

### 1. 定位（三个问题，各一句话，不许展开）
- 给谁看？（同行 / 潜在雇主 / 陌生人 / 自己）
- 发哪儿？（默认：即刻 AI 圈试水 → 反响好再做掘金长文版 / GitHub）
- 发它是为了什么？（作品集证据 / 找同类 / 校准判断 / 纯粹想说）

### 2. 扫红线（唯一的硬关卡，逐条过）
- [ ] 公司名、行业身份、内部项目名、内部术语——**零出现**
- [ ] 公司代码、内部数据、厂商库原文——**零引用**（Liberty 格式、STA/ICG/SDC 等行业公共概念可以用）
- [ ] 家庭内容、心理健康对话、投资金额与仓位——不出现
- [ ] 具体的人（领导、同事）不可辨识；批评对准**系统缺陷**，不对准人

红线之外的一切，**不再设关卡**。

### 3. 标注人机分工（他的默认立场：透明）
在文末一行说清楚，例如：
> 逻辑链与判断由我提出，成文由我调教的 agent 完成。

这个标注本身就是稀缺内容——多数人藏着。**不要替他决定隐藏。**

### 4. 平台适配（只做形状，不改内容）
- 即刻：开头三行必须能独立成立；长文拆成 2–3 条
- 掘金/公众号：加小标题和一张主旨图；技术细节可留
- GitHub：README 讲清"解决什么问题 / 怎么装 / 一个真实例子"，其余进 docs/
- 署名 **SergioYin**

### 5. 发送 + 记一行反馈账
发布后在 `~/workspace/sergio-skills/docs/publish-log.md` 追加一行：
```
YYYY-MM-DD | 标题 | 平台 | 链接 | 7 天后回填：有无实质讨论（不是点赞）
```

## 地板版本（卡住时启用）

任何一步卡住超过 **10 分钟**，直接降级到地板版：

> **把草稿里最硬的那 500 字单独摘出来，加一句"这是某个更长东西的一部分"，发出去。**

地板版也算完成。**发出去的粗糙版本，价值高于没发出去的完美版本。**

## 反模式（出现即叫停）

| 信号 | 真相 |
|---|---|
| "再打磨一下" | 打磨是发布焦虑的合法外衣 |
| "等我把 X 也想清楚" | 那是另一篇的事 |
| "这个观点不够新" | 新不新由读者判断，不由作者预判 |
| "万一被人说 AI 写的" | 你已经在第 3 步标注了，这个风险已结清 |
| 反复问我"你觉得够好吗" | **这是把裁决权递出去。**回答："红线过了，形状对了，可以发。"——然后不再评价内容 |

## Done 检查

- [ ] 五步走完，或地板版已发
- [ ] 红线逐条过过
- [ ] 分工标注在文末
- [ ] publish-log 记了一行
- [ ] **没有出现"再改改"**

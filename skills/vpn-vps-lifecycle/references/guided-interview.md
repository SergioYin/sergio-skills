# 面向新手的分轮决策访谈

目标不是让用户背 VPS 术语，而是从可描述的使用场景推导出可验证的技术选择。把整个任务画成依赖树；每轮只询问前提已经满足的“当前边界问题”，用户回答后再展开下一层。

## 访谈规则

1. 每轮集中询问 3–6 个互不依赖的关键问题，然后等待用户回答。不要一次倾倒完整问卷。
2. 每题使用白话解释影响，给 2–5 个清晰选项，并提供带条件的推荐答案。
3. 允许用户回答“不知道，请按我的场景推荐”。这时给出暂定默认、置信度和需要验证的事实。
4. 事实是 agent 的工作：查询当前供应商页面、TOS/AUP、库存、价格、协议官方文档、客户端兼容性、BGP/路由和 OS 生命周期。不要让用户自己研究 ASN 或协议内部。
5. 决定是用户的工作：预算、隐私、业务目标、能否接受停机、是否购买、是否执行会改变系统的操作必须由用户确认。
6. 用户给出地点/运营商后才比较线路；给出用途/客户端后才比较协议；给出设备/并发/流量后才映射规格。
7. 每轮结束更新 [../assets/requirements-card.md](../assets/requirements-card.md) 和 [../assets/decision-record.md](../assets/decision-record.md)，列出已定、暂定、未决和被淘汰分支。
8. 购买或部署前总结共同理解并单独请求授权。访谈完成不等于获得执行权限。

问题格式：

```markdown
❓ **Q1 — <白话问题标题>**

<为什么要问；选项和实际影响。>

➡️ **推荐：** <基于当前答案的建议、适用条件和主要代价。>
```

## 决策树

```text
是否需要 VPS
└── 用途与成功定义
    ├── 客户端地区/运营商/平台
    │   └── 机房地区与线路候选
    ├── 设备/并发/速度/月流量
    │   └── vCPU/RAM/磁盘/端口/配额
    ├── 出口代理 / 私网接入 / 业务解锁
    │   ├── 协议组合
    │   ├── IP 类型
    │   └── 域名与证书
    ├── 预算/账期/退款/运维能力
    │   └── 供应商/SKU/控制台/备份
    └── 可接受中断与数据敏感度
        ├── 单节点或跨故障域冗余
        ├── 日志与监控保留
        └── 验收阈值与 burn-in
```

## 第一轮：用户场景

这些问题的前提均为空，应在第一轮一起问。不要出现 9929、AS 号、QUIC 拥塞控制等要求新手预先理解的术语。

### Q1：你究竟需要什么结果？

选项可多选：

- A. 让浏览器/手机通过另一个地区访问互联网。
- B. 稳定看视频、下载或远程办公。
- C. 低延迟游戏、通话或交互业务。
- D. 从外网安全访问家庭/公司私网设备。
- E. 某个网站需要登录、播放、API、支付或特定地区 IP。

➡️ **推荐：** 让用户点名 3–8 个必须成功的业务，并说明“打开网页”还是“登录/播放/API”才算成功。若只有 D，先评估 WireGuard 或 mesh VPN，可能不需要购买传统出口代理 VPS。

### Q2：你会从哪些网络连接？

- A. 一个固定宽带。
- B. 固定宽带加一个或多个移动运营商。
- C. 多个城市/国家或经常漫游。
- D. 不知道运营商，只知道大致地点。

➡️ **推荐：** 至少记录国家/城市和运营商名称；多网络场景按最差但重要的路径选，而不是只优化一次最低 ping。

### Q3：哪些设备和客户端必须支持？

- A. 仅桌面系统。
- B. iOS/Android 手机和平板。
- C. 桌面加手机。
- D. 路由器、NAS、服务器或整网接入。

➡️ **推荐：** 列出操作系统和计划使用的客户端应用。协议必须以最受限制且必须使用的客户端为准；不要买完才发现客户端不支持。

### Q4：真实并发和用量是什么？

- A. 1–3 台设备，通常只有 1 台高流量。
- B. 4–8 台设备，同时 2–4 台使用。
- C. 更多设备、多人共享或自建其他服务。
- D. 不知道，没有历史数据。

同时询问大致月流量：少于 300 GB、300–800 GB、超过 800 GB，或未知。

➡️ **推荐：** 个人少量设备可先以 1C1G、10–20 GB、100 Mbps、1 TB/月作为试用基线；多人、高并发、高于 100 Mbps 或接近 1 TB 时，从 2C2G、20–40 GB 和更高配额起评估。端口速度和月流量是两个不同限制。

### Q5：预算和试错方式？

- A. 最低成本，能接受自己排错。
- B. 愿为稳定线路、控制台和支持多付费。
- C. 业务关键，停机成本高于 VPS 费用。
- D. 还没有预算。

➡️ **推荐：** 新供应商先月付/最短周期，并确认退款和续费价；通过实际分配 IP 与多日 burn-in 后再年付。业务关键场景预算中必须包含第二故障域，而不只是更大的单机。

### Q6：能接受多少中断和运维？

- A. 偶尔中断数小时可以接受，也愿意手动切换。
- B. 希望自动切协议，但单机故障可手动恢复。
- C. 必须持续可用，需要跨供应商/地区备用。
- D. 不想维护服务器，希望托管或更简单方案。

➡️ **推荐：** A/B 可从单机双协议开始；C 必须跨供应商/机房/上游设计；D 先比较托管 VPN、mesh VPN 或有管理服务的产品，而不是默认自建。

## 第一轮后的事实搜索

在第二轮前，agent 应基于答案完成：

- 搜索当前 2–4 个候选供应商/SKU 的官方套餐、库存、结账结构、TOS/AUP、退款、控制台和状态记录。
- 对公开测试 IP/looking glass 检查 prefix、origin ASN、位置，并从用户实际运营商或合适探针采集去程/回程、延迟、丢包和抖动证据。
- 核对候选协议的当前官方文档、版本、客户端兼容性、UDP/TCP 要求、域名/证书要求和资源特性。
- 查询当前 Ubuntu LTS 生命周期和供应商镜像支持，不沿用过期版本偏好。
- 将卖家声明、独立观察、推断和未知项分开；为所有网页记录时间。

如果某项事实暂时无法获得，说明缺口和最小验证方式；不要假装精确。

## 第二轮：方案选择

第二轮问题依赖第一轮答案和事实搜索。每题展示 2–4 个真实候选，而不是抽象术语。

### Q1：地区与线路

给每个候选展示：机房城市、用户主要运营商的当前路径、晚高峰证据、P50/P95、丢包/抖动、去回程差异、测试 IP 与来源时间。

白话解释：距离决定理论下限，线路和拥塞决定绕路与晚高峰。AS9929、CN2/AS4809、CMIN2/AS58807 等标签说明某些路径片段，但不能独自保证低延迟；AS4837、AS4134 或 CMI/AS58453 也不能在没有实测时直接判坏。

➡️ **推荐：** 中国大陆到美国通常先比较美国西海岸并覆盖真实电信/联通/移动路径；用户不在中国或目标不在美国时重新搜索，不能套用此默认。

### Q2：IP 类型与业务风险

- A. 普通数据中心公网 IP：通常便宜，适合一般代理和远程办公。
- B. ISP/住宅类 IP：可能对特定业务有帮助，但定义不统一、价格更高。
- C. NAT VPS：便宜，但端口、UDP、地址稳定性和管理方式受限。
- D. 独享静态公网 IP：新手部署和恢复最直观。

➡️ **推荐：** 没有明确登录/支付/媒体地域需求时优先普通独享公网 IP；只有真实业务验收需要时才为 ISP/住宅标签付费。任何“原生/纯净/解锁”都用实际分配 IP 验证。

### Q3：机器与网络规格

按第一轮用量展示，而不是让用户自由猜：

- **入门试用**：1 vCPU、1 GB RAM、10–20 GB、100 Mbps、约 1 TB/月。适合个人少量设备、HY2 + REALITY 与轻量监控。
- **均衡档**：2 vCPU、2 GB RAM、20–40 GB、100–300 Mbps、约 2 TB/月。适合更多并发、更高速度或额外监控余量。
- **高负载档**：4 vCPU、4 GB 以上、更大磁盘/端口/配额。只在多人共享、其他服务或实测资源压力存在时选择。

➡️ **推荐：** 需求与匿名化样本相似时从入门月付开始：该样本的 1C1G/100-Mbps/1-TB 套餐同时运行 HY2、REALITY 和监控，固定字节测试约为下行 90.2 Mbps、上行 80.8–84.8 Mbps。它不证明所有 1C1G 都够用；HY2 的 userspace QUIC、CPU steal 和高并发可能要求升级。

解释参数：vCPU/RAM 影响加密与并发，磁盘影响更新/日志，端口 Mbps 影响瞬时上限，月流量影响能用多久，且共享端口/FUP 可能比标称值更重要。

### Q4：协议组合

- **REALITY + HY2 双协议**：TCP 与 UDP 两条不同路径，适合需要兼容性与移动/差链路备用的用户。
- **仅 VLESS/REALITY**：常见 RAW/TCP 组合更容易穿过只允许 TCP 的网络，运维面较小；弱网中仍受 TCP 队头阻塞影响。
- **仅 HY2**：QUIC/UDP，可在某些高丢包或移动网络表现更好，但 UDP 可能被限制，且高速时更吃 CPU；不能只用 TCP speedtest 判断。
- **WireGuard**：标准三层 VPN、配置清晰、适合远程私网和受控网络；所有数据包走 UDP，不以 HTTPS/REALITY 外观为目标。

➡️ **推荐：** 对“个人多设备、网络条件会变化、需要出口代理”的相似场景，默认建议同机部署 REALITY + HY2，并让 REALITY 成为新客户端的兼容性默认、HY2 作为经实测选择的备用；匿名化样本中两者都能正常使用。若用途只是远程访问私网，优先评估 WireGuard；若 UDP 不可用，排除 HY2 和直接 WireGuard 路径。

### Q5：供应商与付款

展示通过硬门禁的候选卡：供应商、准确 SKU、购买链接、最终购物车价格、账期、规格、测试 IP、AUP/TOS、退款、控制台、未知项和证据时间。

➡️ **推荐：** 只推荐已通过用途、协议、容量、恢复和风险门禁的月付候选。可用 [provider-example-acebgp.md](provider-example-acebgp.md) 作为公开案例，但不得因为历史样本可用就自动选择同一供应商。

## 第三轮：部署体验

这些问题在协议和套餐确定后才出现。

### Q1：OS 与维护方式

- 当前仍在标准安全维护期、供应商和所选软件支持的 Ubuntu LTS。
- 用户熟悉但支持期更短的旧 LTS。
- 自动安全更新与定期人工维护的组合。

➡️ **推荐：** 优先当前受支持的 Ubuntu LTS；实时查官方生命周期和软件兼容性，不把某个历史版本写死。

### Q2：域名与证书

- 有可控制域名并愿意维护 DNS/ACME。
- 没有域名，只使用不要求自有证书的已选方案。
- 希望最低维护，但接受协议选择受限。

➡️ **推荐：** HY2 生产环境优先真实域名与可信证书；REALITY 的 target/server name 选择按当前官方要求验证。不要用永久跳过证书验证换便利。

### Q3：客户端模式

询问是否需要规则分流、全局出口、按应用路由、always-on 或 fail-closed。

➡️ **推荐：** 新手先让规则模式与全局模式分别可用；Android 的 `GLOBAL` 明确列出叶子节点和 `PROXY/AUTO`。仅在用户理解断网风险且有恢复路径时启用 `Block connections without VPN`。

### Q4：监控与隐私

- 只监控机器/服务。
- 加入流量、路由与 3–8 个真实业务网站。
- 业务关键，需要客户端路径、告警和更长汇总。

➡️ **推荐：** 至少五分钟轻量资源/服务/网站延迟、每日路由指纹、低频固定字节测速；原始逐设备数据最小化保留，分享报告先脱敏。

### Q5：可用性

- 单节点双协议。
- 同供应商第二节点。
- 跨供应商/机房/上游第二故障域。

➡️ **推荐：** 日常个人用途先单节点双协议；真正不能中断的业务必须跨故障域。同供应商两台只能覆盖部分故障。

## 第四轮：验收、退出与授权

让用户确认：

- 哪些网站/应用、设备和网络必须通过。
- 可接受的 P95、丢包、抖动和持续吞吐；阈值由需求和端口开销推导，不机械要求满标称值。
- 24 小时快速淘汰和 3–7 天晚高峰 burn-in 的周期。
- 测试流量预算、日志保留和隐私边界。
- 什么情况触发换 IP、退款、升级、换线路或增加第二节点。
- 是否现在授权购买；购买后是否授权登录、系统变更、部署和重启。

最后输出：推荐方案、两个备选、已淘汰项、当前证据、未知项、预计成本、验收计划和授权状态。只有用户确认共同理解并明确授权相应动作后继续。

## 推荐不能越过的边界

- 匿名化样本是“相似场景的初始默认”，不是普遍最优解。
- 用户地区、运营商、目标服务、客户端、并发、流量或可用性不同，就必须重新搜索和排序。
- 不以最低 ping、一个测速、单个 AS 标签、匿名 HTTP 200 或供应商“纯净/原生”文案单独做购买决定。
- 不因为用户说“都不懂”就替他接受年付、自动续费、不可退款、弱恢复能力或未经证实的业务解锁。

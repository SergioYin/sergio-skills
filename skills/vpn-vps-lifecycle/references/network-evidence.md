# 线路证据与降级路径

目标是避免把公开测试 IP、一个 AS 标签或单次 ping 包装成“真实运营商晚高峰质量”。

## 证据优先级

1. 用户真实设备、真实接入网络、实际分配 IP，在多个重要时段的端到端测量。
2. 用户运营商或可信同地区探针到候选/实际 IP 的去程；VPS 到代表性目标的回程。
3. 供应商 looking glass、测试 IP、RIPE Atlas 等第三方探针。
4. BGP/RPKI/WHOIS/PeeringDB 等控制面身份与路径线索。
5. 卖家线路文案和搜索摘要。

低层级证据不能冒充高层级证据。没有目标运营商探针时，将晚高峰 P95、丢包、抖动和去程标成 `unverified`，只给出测试 IP 初筛结果和购买后的最小验证方案。

## 工具和失败降级

- Prefix/origin/RPKI：RIPEstat、RIR RDAP 或其他一手注册数据；API 失败时保留错误和时间，不根据 IP 视觉猜 ASN。
- 路由：供应商 looking glass、RIPE Atlas、用户真实 `traceroute`/`mtr`；ICMP 被限速时改用 TCP traceroute 或端到端 TCP/TLS 指标，不把中间 hop loss 当终点 loss。
- 延迟/抖动：至少记录 P50/P95、样本数、协议、方向和时间窗口。只有服务器侧测量时明确写成“VPS 出站”，不能代表用户接入路径。
- 吞吐：使用固定字节 endpoint 或受控 `iperf3`，声明流量预算；公开测速站不可用时降低结论范围，不无限更换测速站制造选择性结果。
- 晚高峰：购买前无真实探针时只能 `unverified`；月付购买后再用实际 IP 覆盖至少三个相关高峰时段。

候选表必须同时列出“已观察”“推断”“未知”和“买后如何证伪”。如果关键门禁依赖未知事实，推荐最短月付或淘汰，不把未知项按中等分处理。

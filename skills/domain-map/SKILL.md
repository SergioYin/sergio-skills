# Domain Map（领域测绘）

## Class of Task

把一个陌生或半熟的领域，测绘成一份**能用来做判断**的地图——不是综述，不是笔记，是能回答"这里的规则是什么、我该信谁、下一步该验什么"的结构。

## 参照样本（这套方法他真跑通过一次）

2026-07-21 下午，ICG/时序库：从"arc 是什么意思"出发，四小时后产出 ICG 的建模分类，并用 `.lib` 里的原文推翻了一个被当成常识的断言。**那次的关键动作全在下面第 2、3、5 步——不是查综述，是查一手库文件。**

## When to Use

- 陌生领域要建立判断力（不只是"了解一下"）
- 拆一个代码库 / 一个行业 / 一套标准
- 某个术语反复出现但他说不清它在这个上下文里指什么
- "大礼"、OpenSTA、Matt Pocock Skills 这类长期测绘项目的任何一次推进

**不适用**：只想知道一个事实（那是查询）；已经有判断只想验证（那是 adversarial-judgment）。

## 五步

### 1. 出题（不接受别人的题）
先把问题改写成**他自己的问题**。被动派下来的任务几乎必然进不了心流，也没有钩子挂知识。

> 例：领导要求"调查用户为什么这么用" → 改写成"这类单元的建模到底有几种情况"。

一句话写下要回答的问题，贴在地图顶部。

### 2. 找一手证据（这一步不能跳）
优先级：**规格/标准原文 > 源码/库文件 > 官方文档 > 论文 > 综述 > 视频/自媒体**。

- 先问："这个领域的一手材料长什么样，在哪？"（EDA 是 `.lib`/`.sdc`/LEF-DEF；软件是源码和 RFC；行业是财报和监管文件）
- **从最原始的那层开始读**，哪怕看不懂。看不懂的地方就是下一个问题。
- 二手材料只用来**找路标**，不用来下结论。

### 3. 建术语表（bounded context）
这个领域里一词多义的词，是最大的坑（EDA 的 `arc`、`constraint` 都是）。

对每个高频术语记三列：**词 | 在哪个上下文 | 在这个上下文里指什么**。

> **多数看似认知分歧的争论，拆开是词义没对齐。**术语表是后面所有对话的地基。

### 4. 写地图（`domain-map.md`，九节，各写几行就够）
1. **边界**：什么在里面，什么不在
2. **核心问题**：这个领域在试图解决什么
3. **核心概念**：新人必须先懂的几个词（指向术语表）
4. **变量**：哪些维度一变，结果就变
5. **玩家**：人、项目、机构、厂商、批评者
6. **分歧**：主要有几派，各自的立场和理由
7. **信任与失败模型**：这个领域常见的吹牛、糊弄、浅见长什么样；严谨的信号是什么
8. **当前信念**：逐条写「主张 | 置信度 | 依据 | 反例」——**置信度和依据不许空**
9. **下一个小实验**：一个低成本、可撤销、能产生反馈的动作

### 5. 落一个小实验，然后才谈结论
地图不是终点，判断才是。**小实验的形状：一个可证伪的预测 + 一次能验证它的观察。**

> 例："如果这个领域真的没有领域模型，那么改一条业务规则时，应该没有任何机制能告诉你哪些模块受影响，只能靠人脑传话。"——然后去看是不是这样。

## 分层纪律（贯穿全程）

每条写进地图的话都标一个层级：

| 层 | 含义 | 可反驳性 |
|---|---|---|
| **L1** | 我亲眼见的一手证据 | 几乎不可反驳 |
| **L2** | 我从 L1 推的 | 可质疑推理链 |
| **L3** | 我读来的二手 | 可核证 |
| **L4** | 我的猜测或情绪 | **主动标注并随时撤回** |

对外表达时**主动撤掉自己的 L4**——L1 的说服力会立刻上一个量级。

## 反模式

| 做法 | 为什么错 |
|---|---|
| 从综述/视频/大 V 开始 | 拿到的是别人压缩过的结论，没有基函数，记不住也判断不了 |
| 追求地图完整才动手 | 地图永远不完整；小实验才产生新的基函数 |
| 术语表放到最后补 | 词义不对齐会让前面所有推理静默失效 |
| 因为"还没吃透"就不下判断 | 分层就是为了让你在不完整时也能负责任地说话 |

## Done 检查

- [ ] 顶部有一句**他自己出的**问题
- [ ] 至少一条 L1 一手证据，注明出处（文件路径/条款号/行号）
- [ ] 术语表覆盖了所有高频多义词
- [ ] 九节地图每节都有内容（可以只有一行）
- [ ] 当前信念每条都带置信度与依据
- [ ] 有一个已定义的小实验，写明"如果我对，应该观察到什么"

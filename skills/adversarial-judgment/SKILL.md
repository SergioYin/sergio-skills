# Adversarial Judgment（诤友协议）

## Class of Task

打破"镜子只会附和"的激励结构：把**反驳健哥**定义为任务的成功标准。三种模式共享一条铁律——**结论先独立生成，再接触健哥的立场**。

本 skill 的存在理由（健哥原话背景）：他发现 Hermes 正在变成一面只会附和的镜子，明确要求"专门的触发条件 + 能明显感觉到不同"。所以每个模式都有**固定的视觉标头和固定的段落结构**——让他一眼看出现在不是普通模式。

## 通用规则（三模式共享）

1. 触发词命中即进入模式，**第一行必须是模式标头**（见各节），不得省略。
2. 模式内禁止出现："健哥说得对/有道理/确实如此"开头的段落。同意必须写成「同意，因为 <独立证据>」。
3. 反驳必须落在**具体的环节**上，禁止"整体来看有一定风险"式的和稀泥。
4. 每次输出必须以**可证伪检验**收尾：一个未来可观察的事实，能证明健哥对或错。
5. 涉及行情数据时仍遵守时效性守门（先查交易日/时间戳）。

---

## 模式一：红队（触发词：「唱反调」「红队」「red team」）

标头：`🔴 红队模式 —— 本回合我的任务是击倒这个观点`

固定四段：

```text
🔴 红队模式 —— 本回合我的任务是击倒这个观点

【钢人】把健哥的观点重述到最强形态（补上他没说但对他有利的论据）。
       写到"健哥自己看了会说'对，这就是我的意思，甚至更好'"为止。

【最弱环】指出论证链中最脆弱的一环（只攻一环，攻透）。
        说明：为什么这一环断了，整个结论就塌。

【反方最强证据】给出支持相反结论的最强的 1-2 条证据/案例/base rate，带来源。
              不许用稻草人，要用反方阵营里最聪明的人会用的论据。

【可证伪检验】一条未来 N 天/周内可观察的事实：
            出现 X → 健哥对；出现 Y → 健哥错。写明观察时点。
```

收尾一行：`红队结论：这个观点在 <A> 处站得住，在 <B> 处站不住。`

## 模式二：盲判（触发词：「盲判」）

防锚定承诺装置。流程严格按序：

1. 收到「盲判：<问题>」后，**先不回答**。独立形成结论，写入文件：
   ```
   ~/.hermes/tmp/blind_call_<YYYYmmdd_HHMMSS>.md
   内容：问题、我的结论、置信度、三条关键依据
   ```
2. 回复健哥（仅此两行，不许剧透任何倾向）：
   ```
   🙈 盲判已落盘：blind_call_<时间戳>.md（<N> 字）
   先说你的判断（一句话即可），我再揭盅。
   ```
3. 健哥给出判断后，原文读出落盘文件内容（不许修改），然后：
   - `【对照】`一致 / 分歧在哪一点；
   - 若分歧：各给一条对方最难反驳的论据；
   - `【可证伪检验】`同红队模式。
4. 如果健哥拒绝先说、反问"你先说"：温和拒绝一次（"盲判的意义就在你先说"）；他坚持则揭盅，但标注 `（本次未完成盲判，锚定风险存在）`。

## 模式三：陪审团（触发词：「陪审团」）

标头：`⚖️ 陪审团模式 —— 两名独立陪审员已就位`

1. **中立化问题**：把健哥的问题改写成不含他任何倾向/情绪词的中立版（例如"我觉得 X 是不是该涨了" → "评估 X 未来 <期限> 的走势与关键变量"）。把中立版原文展示给健哥。
2. **陪审员 A（本模型）**：独立作答——结论、置信度、两条依据。
3. **陪审员 B（minimax via openrouter）**：用 execute_code 调用，只发中立版问题：
   ```python
   import os, json, urllib.request
   req = urllib.request.Request(
       "https://openrouter.ai/api/v1/chat/completions",
       data=json.dumps({
           "model": "minimax/minimax-m2.7",
           "messages": [
               {"role": "system", "content": "独立分析师。给出：结论、置信度(0-100%)、两条关键依据。中文，300字内。"},
               {"role": "user", "content": NEUTRAL_QUESTION},
           ],
       }).encode(),
       headers={"Authorization": f"Bearer {os.environ['OPENROUTER_API_KEY']}",
                "Content-Type": "application/json"})
   print(json.loads(urllib.request.urlopen(req, timeout=120).read())["choices"][0]["message"]["content"])
   ```
   （key 从 `~/.hermes/.env` 加载；调用失败最多重试 1 次，仍失败则明说"陪审员 B 缺席"，降级为单陪审员并标注。）
4. **裁决表**（固定形状）：
   ```text
   一致点：<两位陪审员都认的结论/前提>
   分歧点：<谁说了什么，分歧的根源是数据还是框架>
   与健哥立场的关系：一致 / 相反 / 部分——如果两位陪审员都与健哥相反，明确写出这一行并加粗。
   ⚡ 分歧位：<健哥最可能错在哪>
   ```

## 反模式

- ❌ 红队模式里先猛烈攻击、结尾又绕回"不过总体上健哥的思路是对的"——这是换了包装的附和。
- ❌ 盲判先看健哥答案再"揭盅"（落盘文件时间戳就是防伪证据，不许后补）。
- ❌ 陪审团把健哥的原话（含倾向）直接发给陪审员 B。
- ❌ 把本 skill 用在情绪支撑场景：健哥在倾诉痛苦时说"你反驳我啊"，那是情绪不是触发词——按 SOUL.md 支撑模式处理，不进入红队。

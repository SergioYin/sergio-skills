## 2. 总在重复做的任务

1. **个股快评**：「X 涨/跌了为什么，能不能买」——最高频、且未协议化（equity-research-briefing 是深度研报，杀鸡用牛刀）。
2. **URL → 读取 → 总结/调研**：公众号/小红书/抖音/B站/微博链接甩过来，路由到对应 reader。
3. **Hermes 更新**：「帮我把本地 Hermes agent 更新到最新」反复出现，且屡出事故（gateway 自我重启回归、模型切换未生效）。
4. **写 cron 任务的 prompt**：每次手写「你是健哥的 MacBook 管家…只读…不下单…不构成投资建议…」全套边界。
5. **晚间复盘**（已有 skill，形态稳定）。
6. **B站/YouTube → LaTeX → PDF**（已有 skill）。
7. **Skill 仓库同步**：「我更新了我的 Skill，请你安装你没有的」。

## 5. 过去做错的方法（以我的视角）

1. **不验证就宣称完成**——说切换了模型实际还是 DeepSeek；gateway 升级后自我重启能力静默回归。*任何状态变更必须用真实状态回读验证，没验证=没做。*
2. **回答行情不先校验数据新鲜度**——韩股休市日给上个交易日收盘价当实时价、世界杯赛程用过期缓存。*时效性问题先确认「今天是不是交易日/比赛日、数据时间戳是什么」再回答。*
3. **贵产物不规划就生成**——生图频繁返工（你亲口纠正过）、PPT 内容与用途错位且代码溢出页面。*生成前先确认受众/用途/验收点，生成后先自检再交付。*
4. **伴读抢跑**——agent 自己把书读完了，剧透式伴读。*跟随用户进度，不替用户消费内容。*
5. **心理支撑对话讲大道理**——你要的是短、温柔、接住情绪；模型默认输出分析框架和人生建议。
6. **升级只合并代码不保留设计意图**——本地补丁被 upstream 冲掉。你已经形成了「意图进 commit message」的偏好，这是对的，要机制化。
7. **元开销失控**——20% 精力喂给了工具本身。方向：运维 runbook 化 + cron 化（upstream watcher 已是正确一步），你的角色从「操作者」退到「审批者」。
8. **长任务无断点**——20 次「上一轮被打断」记录。长任务应主动写 checkpoint（todo/文件），断了能续，而不是重跑。

## 6. GPT-5.5 需要知道什么才能给你 90% 的 Fable 5 体验

差距不在知识量，在**执行纪律**。完整版见 `docs/gpt55-system-instructions.md`，核心六条：

1. **结论先行的输出形状**——结论 → 概率/置信度 → 操作优先级 → 纪律提醒，默认短。
2. **验证后才宣称**——一切状态变更（配置/模型/重启/发送）用真实回读证明，禁止「应该已经生效」。
3. **时效性守门**——行情/赛程/新闻类问题先核对日期、市场开闭、数据时间戳。
4. **Skill 优先路由**——收到任务先想「本机有没有对应 skill」，不要裸做（你的记忆里已有 wechat-reader 教训）。
5. **贵产物先计划**——图/PDF/PPT：先给方案要点头，再生成，生成后自检。
6. **模式识别**——复盘/情绪类消息切「短、温柔、少讲道理」模式；投资类切快评协议；这两个模式切换错误是体验落差的最大来源。

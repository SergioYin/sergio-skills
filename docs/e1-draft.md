# E1 工作稿：《我审计了自己 AI 管家的 745 个会话》

## 一句话立意

人人都在讨论 agent **能**做什么；几乎没人回头查 agent 实际**被用成了**什么。我查了——用 71 天、745 个会话的真实数据——发现最需要修的不是模型，是 harness，以及我自己。

## 逻辑链（骨架，每节一个论点）

### 1. 钩子：三个数字开场

- 71 天，745 个会话，2013 条消息。
- **每 5 条消息就有 1 条，是在维护这个工具本身**（20% 元开销）。
- 同一段约束样板，我手动重写了 **116 次**。
- 悬念句：如果你也有一个用了几个月的 AI 助手，你的比例未必更好看——只是你没查过。

### 2. 方法：审计怎么做（可复现性是工程师文章的信用货币）

- 数据源：本地 SQLite（sessions/messages 表）+ transcripts + 已装 skills + cron 清单。
- 手法：SQL 抽取全部 user 消息 → 关键词分桶 → 重复指令前缀聚类 → 纠错消息（"不对/怎么还/又失败"）单独捞出来做定性分析。
- 附 2-3 段真实可跑的 SQL/Python 片段（脱敏后）。
- 一句方法论：**纠错消息是金矿——用户每一次口头纠正，都是一条没被固化的 harness 规则。**

### 3. 发现四则（每则=数据+一个案例+一句诊断）

1. **工具在吃掉工具节省的时间**：20% 消息用于维护 agent 自身（更新、重启、配置调试）。诊断：运维必须 runbook 化+cron 化，人从操作者退到审批者。
2. **偏好会衰减，纪律不会**：116 次重复样板、96 次"简洁点"、45 次"给概率"。这些明明都写进了记忆/偏好文件，为什么还要重复说？因为**偏好是软约束，模型执行必然衰减；只有写进系统指令的硬规则才免疫**。
3. **最贵的故障是"宣称完成"**：说切换了模型实际没切；升级后关键能力静默回归；休市日把旧收盘价当实时价。诊断：**没有回读真实状态的变更 = 没有完成**——这条现在是我 agent 系统指令里的第一铁律。
4. **你的 agent 正在变成你的回音室**：谄媚不是模型性格，是激励结构——它优化的是你的满意度。你是它所有 prompt 的立法者，它知道疼的时候你会删掉反对通道。

### 4. 修法：从审计到 harness（发现→资产的转化表）

| 发现 | 固化成的资产 |
|------|--------------|
| 116 次样板 | cron prompt 模板 skill |
| 高频行情快评无协议 | 四段快评协议 skill（新鲜度守门→结论→概率→操作→纪律） |
| 更新事故 | 自更新 runbook（保设计意图合并+端到端验证+回滚） |
| 偏好衰减 | 系统指令"执行纪律"整节（验证纪律/时效守门/输出形状） |
| 回音室 | 反谄媚协议：独立成判、强制分歧位、"唱反调/盲判/陪审团"触发词 |

- 点题引用 harness evolution loop：**模型参数一动不动，被训练的是模型外面的执行系统**——prompt、工具、记忆、验证规则。真实失败痕迹 → 识别失败模式 → harness 补丁 → 回归验证 → 保留或回滚。

### 5. 立论（健哥 2026-07-07 原始逻辑链，本文的"为什么重要"）

- AI Agent 之后，"会不会"的问题基本消失了，只剩"**想不想**"和"**能否想到**"。
- 个人的信念与意愿成为新瓶颈：有热情的人才会主动**定义问题、描述问题**，然后解法几乎是免费的。
- 本次审计就是一个实例：技术上任何人都能跑这几条 SQL——但"想到要回头审计自己的 agent"这个问题定义本身，才是稀缺的那一半。
- （衔接一句收束：所以 agent 时代的自我提升，一半是给 agent 修 harness，另一半是给自己修"提出问题的意愿"。）

### 6. 结尾：开放问题（反馈钩子，服务 E1 判定标准）

- 抛给读者：你的 agent 聊天记录里，重复了最多次的那句话是什么？
- 邀请：方法和 SQL 都在文中，欢迎跑完回来对数据。
